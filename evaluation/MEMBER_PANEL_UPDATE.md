# Housing AI - Member Panel Update

Added a new member lifecycle flow:

- Member role concept
- Project application workflow
- Membership request entity
- Owner review capability endpoint (scoped to the owning project)
- Member dashboard entry point
- Available project browsing
- Request status display

The design keeps existing payment and participant logic and changes membership creation from manual owner entry to approval based membership.


## Signup flow update
Create Account now separates Owner and Member roles. Members are not assigned to projects during registration; they browse available projects and apply through membership requests.

## Delivered acceptance flow

1. Create Account → choose Owner or Member → submit profile and a validated Iranian phone number.
2. Owner login opens the existing owner-scoped dashboard. Owner UI has no create/assign-member controls.
3. Member login opens the independent Member Dashboard with profile, project-card marketplace, applications and My Payments.
4. Apply creates a `PENDING` MembershipRequest and stores a payment-history risk snapshot.
5. The owning Owner opens Membership Requests, reviews prior projects, late/overdue counts and risk score, then accepts or rejects. Admin has no membership-review navigation.
6. Accept creates the ProjectParticipant record; payment rows remain generated by the existing Owner payment-round logic.

## API contract added

- `POST /membership-requests/`
- `GET /membership-requests/?member_id=...&status=PENDING`
- `GET /membership-requests/?owner_user_id=...&status=PENDING`
- `PUT /membership-requests/{id}/review`
- `POST /project-owners/create-account` with `role=OWNER|MEMBER` and no `project_id`
- Member accounts are returned by the existing `/project-owners/login` and `/project-owners/demo-accounts` endpoints.

## Scope note

Project `payment_progress`/`progress` and `available_units` are derived by the backend and shared by Owner and Member views. The implementation is intentionally undergraduate-demo scale: no payment gateway, chat, notifications, blockchain or marketplace trading was added. Existing installment, paid, paid_late, overdue, unpaid, penalty and extra-cost-share calculations remain server-side.
